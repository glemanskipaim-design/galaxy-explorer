## MINOR

### M1. "Crédito: Credit: NASA..." (rótulo duplicado) — ImageCaption.tsx
Crédito literal preservado (correto), mas o rótulo fixo duplica quando a fonte
já traz o próprio rótulo (fixture M51: 2 dos 4 créditos ESA começam com
"Credit:"). NÃO remover o prefixo do texto: o literal tem que ficar intacto.
Omitir o rótulo nosso quando a fonte já rotula:

```ts
// domain/imageCredit.ts
/** A fonte ja rotulou o proprio texto ("Credit:", "Image credit:", "Créditos:")? */
const OWN_LABEL = /^\s*(image\s+)?(credits?|cr[eé]ditos?)\s*:/i
export function creditHasOwnLabel(credit: string): boolean {
  return OWN_LABEL.test(credit)
}
```
```tsx
<p className={styles.credit}>
  {!creditHasOwnLabel(image.credit) && <span className={styles.metaLabel}>Crédito: </span>}
  {image.credit}
</p>
```
O helper `captionOf` de Image.test.tsx hoje acopla em `Crédito: ${credit}`;
passa a usar a mesma função (ou casar por `textContent.endsWith(credit)`).

### M2. Estado `loaded`/`failed` do ProgressiveImage não reseta ao trocar `src`
Se o componente for reaproveitado com outro `src` (navegação entre objetos já
em cache no React Query, sem passar por LoadingState), um `failed` antigo
mostra "Falha ao carregar a imagem" para uma imagem válida, e `loaded` antigo
pula o placeholder. Correção mínima no chamador ou no próprio componente:
```tsx
// ObjectImages.tsx
<ProgressiveImage key={hero.url} ... />
```
ou, dentro do componente, envolver o corpo num inner com `key={src}`.

### M3. Acoplamento entre features: ImageUnavailable importa Object.module.css
`features/image/ImageUnavailable.tsx` usa `objectStyles.imagePlaceholder` e
`.rings` de `features/object/Object.module.css`. Com ImagePlaceholder removido,
esse CSS só serve à feature image. Mover `.imagePlaceholder`, `.rings*` para
`features/image/Image.module.css` (renomeando para `.unavailable`/`.rings`) e
apagar de Object.module.css.

### M4. Instrumento descartado em silêncio quando `mission === null` — ImageCaption.tsx
`instrument` só aparece aninhado em `mission`. Campo fornecido pela fonte some
sem aviso. Ex.:
```tsx
{(image.mission ?? image.instrument) !== null && (
  <li>
    <span className={styles.metaLabel}>Missão/instrumento: </span>
    {[image.mission, image.instrument].filter((v) => v !== null).join(' · ')}
  </li>
)}
```

### M5. Tipagem frouxa do mapa de ícones — ImageKindBadge.tsx
`const ICON: Record<string, string>` aceita variante inexistente e não acusa
variante nova sem ícone. Use o tipo fechado:
```ts
const ICON: Record<ImageKindInfo['variant'], string> = { photo: '◉', survey: '▦', warning: '✎', unknown: '?' }
```
(exportar `ImageKindInfo` já existe em domain/imageKind.ts). Idem `KINDS` em
imageKind.ts poderia ser `Record<KnownImageKind, ImageKindInfo>` com a união
literal separada do `(string & {})`.

### M6. `<span />` vazio no caso sem miniatura — ResultThumbnail.tsx
O filler existe só para ocupar a 2ª coluna do grid; sem comentário parece
resto. Ou comente (`{/* ocupa a coluna de texto: mesma altura do item com imagem */}`),
ou troque por `<span className={styles.thumbText} />`.
