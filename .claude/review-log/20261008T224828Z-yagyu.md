## MINOR
1. termsUrl de recorte sem validação de esquema (CutoutIngestion -> obs_copyright_url do `properties` HiPS).
   O ReferenceURL da AVM exige `https://` (AvmCandidateEvaluator:81), mas `obs_copyright_url` vai para
   `terms_url`/DTO sem checagem. Se o 3b usar esse valor como `href`, um `javascript:`/`data:` vindo da
   fonte (ou de um espelho comprometido) vira XSS ao clicar. Probabilidade baixa (host na allowlist).
   Correção: aceitar só `https://` (senão null) na ingestão; e no 3b validar o esquema de toda URL
   externa antes de usar como `href` (pageUrl, termsUrl, license.url).
2. Arquivos órfãos sem coleta. `deleteForSourceExcept` / upsert com sha novo apagam/trocam linhas, mas
   o arquivo em `data/images` fica para sempre; o import on-demand (público, anônimo) agora também gera
   recortes. Crescimento é limitado (recorte 800x600, poucos por objeto; fila de import limitada), mas
   não tem teto. Correção: tarefa de GC (arquivos cujo sha não está em content_sha256/thumb_sha256,
   com idade mínima para não correr com gravação em andamento) e/ou monitoração de uso de disco.
3. Limite de pixels folgado para o heap. `max-pixels: 40000000` permite decodificar um BufferedImage de
   ~120-160 MB no Thumbnailer, e imports on-demand podem rodar recortes em paralelo. As fontes reais
   são <= 1280 px de largura / 800x600. Correção: baixar para ~16-25 MP; um OutOfMemoryError não é
   capturado pelos `catch (RuntimeException)` do ImportJobWorker/EsaIngestion.
