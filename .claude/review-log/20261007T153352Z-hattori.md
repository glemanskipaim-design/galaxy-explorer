## MINOR

**M1. `AbsenceNotice` inventa um motivo quando `absence === null`.**
Arquivo: `frontend/src/features/object/AbsenceNotice.tsx:7-8`.
O tipo aceita `Absence | null`, e com `null` a UI afirma "Não disponível na fonte". O backend hoje nunca
manda `null` com `available:false` (`ObjectQueryService.absent` sempre preenche o motivo), então isso não
acontece em produção. Mesmo assim, é exatamente o tipo de default que mascara `null` com um motivo que a
API não deu. Correção:
```tsx
const text = absence === null
  ? 'Indisponível (a API não informou o motivo)'
  : absence.code === 'NOT_PROVIDED_BY_SOURCE' ? 'Não disponível na fonte' : absence.message
```

**M2. `resolveShortcuts` mostra "em breve" quando o código some da resposta da API.**
Arquivo: `frontend/src/domain/categoryShortcuts.ts:48-50`.
Se o backend renomear `galaxy`, o atalho mostra "em breve", um motivo falso para o que na verdade é
divergência de contrato. A mesma frase cobre duas situações diferentes: categoria existe com 0 objetos,
e código inexistente. Correção: separar os ramos.
```ts
if (!found) return { ..., disabledReason: 'categoria não encontrada no catálogo' }
if (found.objectCount <= 0) return { ..., disabledReason: s.pendingNote }
```

**M3. `formatDistance` assume que o valor está em pc sem conferir `m.unit`.**
Arquivo: `frontend/src/domain/format/distance.ts:80-81`. A escolha do ramo usa a string mágica
`propertyCode === 'distance'` em `frontend/src/features/object/MeasurementValue.tsx:50`.
Se a unidade canônica mudar, a UI rotula números errados como pc/anos-luz. Correção sem custo: o null já
faz cair em `formatMeasurement`, que mostra a unidade real.
```ts
if (m.value === null || m.unit !== 'pc') return null
```

**M4. `MeasurementValue` esconde `derivedFrom` e pode renderizar `<p>` vazio.**
Arquivo: `frontend/src/features/object/MeasurementValue.tsx:68-82`.
O `<p>` abre com `derived || m.method`, mas "calculado a partir de" só aparece se
`epistemic === 'computed_by_us'`. Com `derivedFrom` preenchido em outro epistemic e `method` nulo, sai um
`<p>` vazio. Além disso, a origem fica oculta para valores `derived_by_source`, o que vai contra "todo
valor com proveniência". Correção: mostrar `derivedFrom` sempre que existir e trocar só o verbo.
```tsx
const verb = m.epistemic === 'computed_by_us' ? 'calculado por nós a partir de' : 'derivado de'
```

**M5. `MeasurementValue` calcula duas vezes e usa um truque de formatação.**
Arquivo: `frontend/src/features/object/MeasurementValue.tsx:50-52, 23`.
- `limitPrefix(m.limitFlag)` duplica `formatted.limit`.
- `formatMeasurement(m)` é calculado mesmo quando o ramo de distância é usado.
- `withUnit('', unit)` é um truque para obter o espaço inicial.

Correção: calcular `formatted` só no ramo `else` e usar `formatted.limit`. Para a unidade, passar o valor
real ao helper (`withUnit(value, unit)`) ou expor um `unitSeparator(unit)` explícito em `units.ts`.

**M6. Regra de algarismos significativos duplicada.**
Arquivo: `frontend/src/domain/format/distance.ts:82`. Repete literalmente `significantDigitsFor(m)` de
`measurement.ts:30-32`, inclusive o `?? 4` mágico. Correção: importar `significantDigitsFor` de
`measurement.ts`, ou mover a função para `number.ts` e as duas usarem. Dar nome ao 4 também:
`DEFAULT_SIGNIFICANT_DIGITS`.

**M7. Montagem de rotas espalhada pelo código.**
Construção duplicada em 7 lugares:
- `/objects/${encodeURIComponent(...)}` em `SearchResultItem.tsx:8`, `ObjectList.tsx:10` e
  `ImportProgress.tsx:35,71,78`;
- `/categories/${encodeURIComponent(...)}` em `ObjectHeader.tsx:12` e `categoryShortcuts.ts:54`.

Os padrões vivem em `App.tsx`. Já existe `qk` para chaves de query, e o equivalente para rotas está
faltando. Correção: criar `src/routes.ts` com
`export const paths = { object: (slug: string) => \`/objects/${encodeURIComponent(slug)}\`, category: ..., search: (q) => ... }`
e usar também em `AppShell.HeaderSearch` e `ObjectPage`.

**M8. Checagem de status de `ApiRequestError` repetida.**
Aparece em 4 lugares: `CategoryPage.tsx:26`, `ObjectPage.tsx:44`, `ImportProgress.tsx:44` (404) e
`ImportOffer.tsx:32,38` (429). Correção em `api/http.ts`:
```ts
export function hasStatus(e: unknown, status: number): e is ApiRequestError {
  return e instanceof ApiRequestError && e.status === status
}
```

**M9. Rótulos diferentes para a mesma ausência de categoria.**
`'Sem categoria'` aparece em `SearchResultItem.tsx:11` e `ObjectList.tsx:12`. `'Sem classificação'`
aparece em `ObjectHeader.tsx:16`. A ausência é a mesma (`category`/`categoryName` null). Correção: uma
constante `NO_CATEGORY_LABEL` em `domain/` usada nos três.

**M10. Erros 4xx determinísticos oferecem "Tentar de novo".**
Arquivos: `SearchResults.tsx:33`, `CategoryPage.tsx:36`, `ObjectPage.tsx:54`.
`ErrorState` recebe `onRetry` mesmo para erros que nunca vão mudar, como 400 da busca com `?q=` de mais de
100 caracteres ou 400 de `offset` fora da faixa. Isso contradiz `shouldRetry`, que nunca repete 4xx.
Correção: `onRetry={isRetryable(error) ? ... : undefined}`, reaproveitando a mesma regra de
`shouldRetry`.

**M11. `CategoryPage.pageFrom` aceita páginas que o backend recusa.**
Arquivo: `frontend/src/pages/CategoryPage.tsx:13-16`.
O regex aceita `?page=` até 9999, mas o backend limita `offset` a 10000, ou seja, página ≤ 417 com 24 por
página. A página 418 em diante vira um 400 genérico com botão de retry. Uma página acima de `pageCount`
mostra "página 50 de 2". O limite de 10000 está duplicado de forma implícita. Correção: exportar
`CATEGORY_MAX_OFFSET = 10_000` em `config.ts` (comentado como espelho do `@Max` do controller) e calcular
`maxPage = Math.floor(CATEGORY_MAX_OFFSET / CATEGORY_PAGE_SIZE) + 1`. Página fora da faixa vira mensagem
explícita "Página N não existe (esta categoria tem X páginas)" com link para a última.

**M12. Dependências entre camadas invertidas.**
- `components/layout/AppShell.tsx:3` importa `features/search/SearchBox`. Pela direção do plano,
  `components` fica abaixo de `features`.
- `components/ui/errorMessage.ts` importa `api/http`.
- As pages importam o CSS de feature (`CategoryPage.tsx:7`, `ObjectPage.tsx:10`).

Hoje funciona. Sem lint de fronteira, porém, a próxima dependência invertida passa despercebida.
Correção: mover `AppShell` para `features/layout/` (ou `app/`), mover `errorMessage` para `api/` (ele
interpreta `ApiRequestError`), e dar a `CategoryPage`/`ObjectDetailView` um componente de feature que
encapsule o próprio layout em vez de a page usar `styles` alheio.

**M13. Casts repetidos em `conflict.ts`.**
Arquivo: `frontend/src/domain/conflict.ts:37-38`. `first.value as number` é repetido dentro do loop. O
`filter` já garante não-nulo, mas o tipo não acompanha. Correção: um type guard

**M14. Fallbacks inalcançáveis e ternário aninhado em `ImportProgress`/`ImportOffer`.**
- `ImportProgress.tsx:32,71` usa `data.resultSlugs[0] ?? ''`, que montaria `/objects/` se algum dia
