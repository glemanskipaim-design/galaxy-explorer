seguinte diz "nada a fazer". O README ("Se a rede falhar: o passo que falhou sai com erro, o marcador
nao e gravado") e o CHANGELOG ("retomavel") prometem algo que o passo 2 nao cumpre. O passo 1
ganhou exatamente essa semantica (`exitCode(..., onlyMissing)`); o passo 2 ficou assimetrico.

```java
@Value("${galaxy.images.run.strict:false}") boolean strict
...
int code = report.anyRunFailed() || (strict && report.outcomes().stream().anyMatch(o -> o.kind().failure())) ? 1 : 0;
```
e em `seed.sh`: `... --galaxy.images.run.objects=all --galaxy.images.run.strict=true`.
Alternativa minima se nao quiser mexer no Java agora: corrigir o README para dizer que falha
parcial de imagens grava o marcador e exige `GALAXY_SEED_FORCE=1`.

### M2. Marcador vive no diretorio de imagens; com `GALAXY_IMAGES_DIR` bind mount ele sobrevive a `down -v`
O README (secao "Beta e desenvolvimento no mesmo banco") recomenda `GALAXY_IMAGES_DIR=./backend/data/images`.
Nesse caso `docker compose down -v` apaga o volume do banco, mas nao o bind mount: o marcador
`.galaxy-seed-complete` continua la e a proxima subida pula a carga com o banco vazio. Tambem
contradiz a linha do README "`down -v` ... APAGAR banco e imagens (proxima subida recarrega)", e o
marcador passa a poluir o diretorio de dev. O estado "carga concluida" e do banco, nao das imagens.
Correcao preferida: dispensar o marcador para o passo 1 (only-missing ja e idempotente e barato) e
guardar o "concluido" no proprio banco (ex. ultimo `ingestion_run` SEED/imagens com status OK), ou
no minimo documentar: "com GALAXY_IMAGES_DIR, apague `backend/data/images/.galaxy-seed-complete`
apos `down -v`".
